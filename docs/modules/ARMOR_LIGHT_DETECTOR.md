# 独立灯条检测

`armor_light_detector` 在每个有效 BGR/灰度同帧图像上执行全图 OpenCV 轮廓检测，默认启用。
它不依赖其他仓库源码，也不复用角点精修器；输出只能辅助已由完整装甲 PnP 初始化的13维
ESEKF，不能从 LOST 初始化跟踪器。

## 检测流程

检测器先从网络装甲的左右灯条采样灰度。角点精修成功时使用完整精修四角，否则原子回退到
网络 TL/TR/BR/BL。有效参考的平均亮度减50后限制到 `[60,240]` 作为二值阈值；没有有效参考
时使用120。随后以 `RETR_EXTERNAL` 和未压缩轮廓提取前景，`minAreaRect` 长边中点作为上下
端点，并按图像 y 从小到大固定顺序。方向角定义为从 top 指向 bottom 的
`atan2(delta_u, delta_v)`，0表示图像竖直向下。

默认几何门限为轮廓至少6点、面积至少2 px²、长度至少3 px、宽长比 `[0.02,0.40]`、相对
竖直倾角不超过0.70 rad。轮廓内部按敌方颜色计算 `R-B` 或 `B-R` 通道差，至少为20；最终按
`颜色差*轮廓面积` 降序保留最多64根。空图、类型或尺寸不匹配只返回空结果与
`invalid_image`，不会重置预测器；配置未知字段或范围错误在启动时失败。

严格 schema 1 配置位于 `src/config/modules/armor_light_detector.yaml`，包含启用开关、固定与
自适应阈值范围、轮廓几何、颜色差和最大候选数。主链顺序为网络检测、灰度转换、角点精修、
独立灯条检测、PnP、装甲/灯条联合 ESEKF、控制与 Foxglove。

## 诊断与验收

`/vision/lightbars/annotations` 显示原始/拒绝灯条、完整装甲重复灯条、预测灯条和正式接受
灯条；`/vision/lightbars/stats` 提供实际阈值、来源、各级筛选数、检测耗时和融合计数。
`/vision/prediction/state.lightbar_associations` 记录输入编号、槽位、左右身份、预测/实测端点、
代价分量和拒绝原因。没有完整装甲时，只有同一槽位的左右灯条完整配对才允许更新；单根灯条
显示为红色并记录 `insufficient_light_only_geometry`，随后由预测器进入 TEMP_LOST 预测，
不会以弱可观测的单线残差继续修改13维状态。

仿真验收重点检查：灯条检测耗时 P95 不超过2 ms；完整装甲内灯条不重复融合；没有独立匹配时
滤波行为与基线一致；联合 NIS 拒绝可回退到完整装甲；灯条-only 可维持或恢复跟踪但不能从
LOST 初始化，且每次提交至少包含一个同槽左右灯条对；不新增数值重置、异常退出或发弹脉冲。
真实相机、场地光照和发弹待用户实机验证。
