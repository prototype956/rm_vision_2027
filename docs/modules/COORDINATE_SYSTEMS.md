# 坐标系与 Talos 帧契约

视觉空间链统一写作：

```text
world -> gimbal -> camera_optical -> armor
```

`ᵃT_b` 表示将 `b` 坐标系中的点变换到 `a` 坐标系，因此相机世界位姿为：

```text
ᵂT_camera = ᵂT_gimbal · ᵍT_camera
```

## 坐标系

- `world`：仿真固定右手系，x/y 位于地面，z 向上。
- `gimbal`：原点位于云台旋转中心，x 沿发射方向，y 向左，z 向上。
- `camera_optical`：OpenCV 光学坐标，x 向图像右侧，y 向下，z 向前。
- `armor`：x 向装甲右侧、y 向上、z 指向正面；仿真 GLB `CENTER` 的对应局部轴为
  `+X/+Z/-Y`，装甲平面是 XZ 而不是 XY。
- `car`：车辆模型坐标，x 指向四装甲槽位0，z 为底盘 yaw 旋转轴；槽位绕 +Z 每次增加
  90°。视觉侧 armor 的局部 XY 是几何观测平面，+Z 始终是正面法向。
- 平移单位为米，旋转角单位为弧度；四元数使用具名的 `x/y/z/w` 分量。

仿真端根据物理轴构造 `ᵂT_gimbal` 和 `ᵂT_camera_optical`，再计算
`ᵍT_camera = inverse(ᵂT_gimbal) · ᵂT_camera_optical`。视觉端不得重新解释或修正这些轴。

## Talos v6 同步规则

Talos v6 将图像缓冲编号、采集序号、epoch 纳秒时间戳、内参、TF、底盘观测、弹丸累计统计和
真值放在同一个 `CapturedFrameMeta` 三缓冲槽中。发布端先写图像像素，最后原子提交元数据；
消费端一次只消费一个完整槽位。v6 使用 v5 的 32 字节保留区承载统计，不改变整体 ABI 大小
和关键偏移，但 magic/version 均已升级，旧 v5 二进制会被明确拒绝。

视觉端要求：

- 序号和采集时间戳严格递增，允许序号跳跃。
- 图像尺寸与内参尺寸相同，`fx/fy` 为正。
- 变换数值有限，四元数模长与 1 的误差不超过 `1e-3`。
- 真值批次及目标的序号、时间戳必须与图像相同。
- 弹丸统计时间戳必须与图像相同；计数是进程启动以来的单调累计值。
- 无效帧直接丢弃，不使用上一帧空间数据兜底。

每块装甲真值包含稳定 ID、队伍、标签、大小类型、`T_world_armor`、尺寸及按
TL/TR/BR/BL 排列的灯条端点世界坐标。装甲坐标系 x 向右、y 向上、z 指向正面。

`receive_steady_time` 只用于进程内限流和发布延迟；仿真采集时间用于图像、TF、Scene 和
MCAP 同步，两者禁止混用。

## 第一阶段投影验收

视觉端按下式将装甲真值四角投影到图像：

```text
ᶜp = inverse(ᵂT_gimbal · ᵍT_camera) · ᵂp
u = fx · x/z + cx
v = fy · y/z + cy
```

只显示 `z > 0` 且与图像范围相交的装甲。真值投影既用于验证坐标链，也作为 PnP
数值基准输入；检测器仍只能读取原始图像。

## 仿真验收顺序

1. 静止底盘和云台，在 Foxglove 以 `world` 为固定坐标系检查三根坐标轴、视锥和投影点。
2. 分别执行纯 yaw、纯 pitch 和组合云台运动，确认世界真值不随相机漂移。
3. 固定云台并移动、旋转底盘，确认投影没有一帧延迟。
4. 底盘、云台和目标组合运动至少 5 分钟，同时录制 MCAP；全部调试话题必须使用同帧时间戳，
   时间戳序列完全相同且严格递增，日志中不得出现 Talos 无效帧。
