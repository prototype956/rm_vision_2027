# 坐标系与 Talos 帧契约

视觉空间链统一写作：

```text
world -> gimbal -> camera_optical -> armor
```

`ᵃT_b` 表示将 `b` 坐标系中的点变换到 `a` 坐标系，因此相机世界位姿为：

```text
ᵂT_camera = ᵂT_gimbal · ᵍT_camera
```

## 坐标系

- `world`：仿真固定右手系，x/y 位于地面，z 向上。
- `gimbal`：原点位于云台旋转中心，x 沿发射方向，y 向左，z 向上。
- `camera_optical`：OpenCV 光学坐标，x 向图像右侧，y 向下，z 向前。
- 平移单位为米，旋转角单位为弧度；四元数使用具名的 `x/y/z/w` 分量。

仿真端根据物理轴构造 `ᵂT_gimbal` 和 `ᵂT_camera_optical`，再计算
`ᵍT_camera = inverse(ᵂT_gimbal) · ᵂT_camera_optical`。视觉端不得重新解释或修正这些轴。

## Talos v4 同步规则

Talos v4 将图像缓冲编号、采集序号、epoch 纳秒时间戳、内参、TF、底盘观测和真值放在
同一个 `CapturedFrameMeta` 三缓冲槽中。发布端先写图像像素，最后原子提交元数据；消费端
一次只消费一个完整槽位。v2/v3 不再兼容。

视觉端要求：

- 序号和采集时间戳严格递增，允许序号跳跃。
- 图像尺寸与内参尺寸相同，`fx/fy` 为正。
- 变换数值有限，四元数模长与 1 的误差不超过 `1e-3`。
- 真值批次及目标的序号、时间戳必须与图像相同。
- 无效帧直接丢弃，不使用上一帧空间数据兜底。

`receive_steady_time` 只用于进程内限流和发布延迟；仿真采集时间用于图像、TF、Scene 和
MCAP 同步，两者禁止混用。

## 第一阶段投影验收

仿真仅提供装甲 `CENTER` 节点的世界坐标作为投影探针，不提供装甲姿态、物理尺寸或四角点。
视觉端按下式投影：

```text
ᶜp = inverse(ᵂT_gimbal · ᵍT_camera) · ᵂp
u = fx · x/z + cx
v = fy · y/z + cy
```

只显示 `z > 0` 且位于图像范围内的点。该结果只用于验证坐标链，不得输入检测器或后续 PnP。

## 仿真验收顺序

1. 静止底盘和云台，在 Foxglove 以 `world` 为固定坐标系检查三根坐标轴、视锥和投影点。
2. 分别执行纯 yaw、纯 pitch 和组合云台运动，确认世界真值不随相机漂移。
3. 固定云台并移动、旋转底盘，确认投影没有一帧延迟。
4. 底盘、云台和目标组合运动至少 5 分钟，同时录制 MCAP；九个调试话题必须使用同帧时间戳，
   时间戳序列完全相同且严格递增，日志中不得出现 Talos 无效帧。
