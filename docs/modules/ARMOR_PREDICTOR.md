# 装甲目标13维 ESEKF

`armor_predictor` 直接维护四装甲整车状态，常规滤波更新融合检测四角拆出的灯条和全图 OpenCV
独立灯条图像观测。当前支持 `SENTRY`、`ONE`、`TWO`、`THREE`、`FOUR`；不支持5号、前哨站
和基地。PnP 不再作为常规位姿量测，只承担 LOST 初始化、单装甲左右灯条深度差和既有诊断。

## 状态与坐标契约

名义状态包含 world 系车辆中心与速度、将 car 向量旋转到 world 的单位四元数、车体系 z 轴
yaw 角速度、`log(r1)`、`log(r2)` 和奇数槽位高度差。固定13维误差/诊断顺序为：

```text
cx,vx,cy,vy,cz,vz,rot_x,rot_y,rot_z,vyaw,log_r1,log_r2,h
```

姿态误差在右侧注入：`q <- q * Exp(delta_theta)`。预测使用三轴匀速和
`q <- q * Exp([0,0,vyaw*dt])`；车体系加速度噪声按当前姿态旋转到 world。预测和观测
Jacobian 均用 `ceres::Jet<double,13>` 对局部误差自动求导，迭代更新使用 IESEKF 先验修正、
LDLT、Joseph 协方差更新、右注入协方差重置和对称化。

car 系 x 向槽位0、z 为旋转轴。槽位依次绕 car +Z 相差90°，偶数槽位使用 `r1`，奇数槽位
使用 `r2` 并沿 car +Z 增加 `h`。armor 局部 XY 是装甲平面，+Z 指向正面；安装倾角绕 armor
局部 +X。该模型遵循本项目坐标契约，不使用其他项目的负 X 法向约定。

## 初始化、关联与观测

角点精修成功时整块采用四个精修角点，否则整块回退网络 TL/TR/BR/BL。LOST 只从成功
IPPE 的检测候选初始化，先按标签优先级、再按到主点距离选择；将观测装甲视为槽位0，并由
`world_T_armor`、初始半径和固定安装倾角反求完整 `world_T_car`。

已跟踪状态先投影四个槽位，按正面可见性保留最多三个。关联代价由中心像素距离、四边方向
误差均值和周长比对数误差组成，并穷举得到“匹配数最大、总代价最小”的全局一对一结果。
每块匹配装甲拆为两条 `UVL=[angle,center_u,center_v,length]` 联合更新；仅匹配一块且该检测
IPPE 成功时，额外使用左右灯条中心在 camera optical Z 上的深度差。

完整装甲全局关联完成后才处理独立灯条。候选与已关联装甲灯条的中心距离、方向差和长度比
同时落入门限时标记为 `duplicate_full_armor`，不会重复更新；已被完整装甲占用的
`(slot,left/right)` 身份也从独立候选中移除。剩余候选与最多三个可见槽位的左右灯条进行
位掩码动态规划，目标为匹配数最大、总代价最小。单对硬门限检查长度对数比、方向差和归一化
端点距离，代价为 `端点距离比例 + 2*方向差 + 长度比例误差`。每根匹配独立灯条生成一条
UVL，并使用比完整装甲更保守的中心、长度和方向噪声。

有完整装甲时，预测器分别在基准副本上执行“仅完整装甲”和“装甲+独立灯条”试更新。联合
先验 `NIS/DOF` 通过才提交；联合门控失败但装甲基准通过时提交基准结果，并把独立灯条记为
`combined_nis_gate`。没有完整装甲时，只有同一槽位的左右独立灯条都关联成功，才会构成一个
具备装甲宽度约束的灯条对并进入试更新；单根或跨槽未配对灯条存在投影零空间，不能充分约束
车辆中心、深度、半径和姿态，因此标记为 `insufficient_light_only_geometry`，不修改状态或
协方差。无有效灯条对时按普通失配进入 TEMP_LOST 并使用现有预测窗口；灯条对可维持或恢复
TRACKING/TEMP_LOST，在 DETECTING 中只能维持候选，不能增加初始化确认帧数。LOST 始终只能
由成功 IPPE 的完整装甲初始化。独立灯条关联代价不参与机动触发，灯条对联合更新的先验 NIS
仍按现有机动逻辑处理。

稳态使用 yaw 角加速度方差30和关联门限200。机动状态分为 `idle`、`pending`、`active`：接受
关联的最大代价达到50、正常门限失败但恢复门限500获得匹配，或稳态试更新的先验
`NIS / residual_dimension` 超过3，均构成一帧机动证据。首帧证据只进入 `pending`，下一视觉帧
在0.15秒内再次出现证据才确认；无连续证据立即回到 `idle`。

确认当帧仅在候选滤波器副本上补加触发方差10000，候选通过 NIS 门控后才提交；拒绝不会污染
正式协方差。`active` 固定保持0.30秒且不被高代价续期，期间预测使用方差2500，到期后重新
经过两帧确认才能再次激活。恢复门限仅在 active 或正常关联全部失败时使用，不会永久放宽
普通关联。

图像更新使用更新前的观测创新、Jacobian 和先验协方差计算标准 NIS，再在 ESEKF 副本上完成
迭代。只有 `NIS / residual_dimension <= 3` 时才提交候选后验；超限观测记为 `nis_gate` 并按
本帧失配处理，不修改正式状态或协方差，也不触发数值重置。被像素门限拒绝的检测仍记录最近
候选槽位、实际代价分量和预测轮廓，便于区分轻微越界与完全错配。

PnP 失败不会阻止已跟踪目标的 UVL 更新。检测与精修数量不一致、标定无效、同帧变换缺失、
非有限状态、LDLT 失败、半径越界、`|h|>0.5 m` 或 `|vyaw|>20 rad/s` 均以明确原因安全
重置，不向主循环抛出数值异常。状态机仍为 LOST、DETECTING、TRACKING、TEMP_LOST。

## 配置、输出与验收

严格 schema 6 位于 `src/config/modules/armor_predictor.yaml`。`light_association` 描述去重、
硬门限和代价权重，`measurement` 包含独立灯条 UVL 噪声；`maneuver` 配置段固定描述触发
代价、确认帧数和窗口、固定活动时间、触发/活动 yaw 噪声、恢复门限和先验归一化 NIS 门限。
公共结果同时提供13维诊断数组和
具名中心、速度、完整姿态、角速度、双半径、高度差、中心协方差与由 SO(3) 切空间投影得到的
yaw 方差。未来姿态按完整四元数外推，火控、槽位选择、弹道和 MPC 只读取这些具名字段。
当前 `fire_control.yaml` 只为 Talos 仿真默认开启自动发弹；应用仅在
`camera.backend=talos` 时创建命令运行时，实机相机后端不加载发弹输出。F5 外部控制和既有
跟踪、时效、不确定度、弹道、MPC、瞄准稳定及冷却门控仍全部生效。

Foxglove 保持 `/vision/prediction/*` 话题名称。`state` 提供状态顺序、协方差、先验创新/NIS、
机动阶段、连续证据、确认/活动剩余时间、实际 yaw 过程噪声、试更新角速度变化、关联门限与
计数、逐灯条关联、同槽灯条对数量、light-only阻止原因、融合/灯条-only/装甲回退状态、
单调重置计数、估计耗时和 Talos
中心/yaw/yaw角速度误差。原始 yaw 误差保留槽位相位，`truth_yaw_equivalent_error_rad` 将误差
折叠到四装甲 `pi/2` 对称区间用于验收；`scene` 显示车体三轴、双半径和当前/未来装甲；
`current_annotations` 同时显示实测与关联前预测轮廓，
`future_annotations` 显示100 ms重投影。

灯条检测与融合另见 `ARMOR_LIGHT_DETECTOR.md`。本阶段不增加独立验收程序。按
Release/OpenVINO 构建后使用 Talos/Foxglove 依次录制收敛后
至少15秒静止、`0 -> +7.42 rad/s`、停止、`0 -> -7.42 rad/s`（三个稳态各至少20秒）、
直线/横向移动、云台组合运动、1至3个视觉帧短时遮挡和最终至少5分钟连续闭环。稳态中心、
对称 yaw 和角速度误差 P95 门限分别为0.10 m、0.05 rad和0.20 rad/s；`0 -> +/-7.42 rad/s`
切换后0.5秒内角速度误差应回到0.5 rad/s以内；稳态角速度误差最大值不超过0.5 rad/s，真实
角速度突变窗口外 active 帧占比不超过1%。检测持续存在时不得回到 LOST，TEMP_LOST不得连续
超过3个视觉帧，突变中心误差不得超过0.20 m。5分钟内不得出现数值重置、异常退出或发弹脉冲。
MCAP 仅由操作者手动录制；相机实机和真实发弹均待用户实机验证。
