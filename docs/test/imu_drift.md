# IMU 静止漂移实验

用于确认机械静止时，IMU 输出姿态是否随时间偏移，并保留后续补偿研究的数据。
仅发送握手、时钟同步；不发送云台控制，不应用任何补偿，不修改部署参数。

## 准备

- 固定底盘、大 yaw、小 yaw、pitch；防止电机失能后机械缓慢回落。不要手扶云台。
- 全程保持电机使能状态一致，记录该状态。避免明显振动，枪口尽量水平。
- 停止使用同一串口的视觉主程序及其他采集工具，确认用户具有串口访问权限。
- 首轮建议冷机上电后立即开始，持续 15 分钟；再录一次热机数据，条件允许时重复断电上电。
- 计时从首个同步有效姿态开始，因此不包含握手之前的姿态；不自动丢弃预热数据。

## 启动

统一入口 `./scripts/calibrate_camera.sh` 的主项 `4`「IMU 检查」提供静止漂移采集和
离线分析；采集可填写时长、电机状态、冷/热机和备注。默认 900 秒、状态 unspecified。
菜单和类型筛选详见 [统一入口](../tool/CALIBRATION.md)。

```bash
./scripts/calibrate_camera.sh imu-drift capture

./scripts/calibrate_camera.sh imu-drift capture --duration 900 \
  --motor-state enabled --thermal-state cold --note '整车固定，枪口水平'

./scripts/calibrate_camera.sh imu-drift capture --device /dev/ttyUSB0 --duration 120

./scripts/calibrate_camera.sh imu-drift analyze artifacts/imu_drift/<会话目录>
```

脚本从任何目录启动均切换到项目根目录；相对路径参数按项目根目录解释。
优先使用已构建程序，找不到时独立编译到 `build-imu-drift/`。独立构建需要
C++20、Eigen3、yaml-cpp、spdlog、fmt 和 pthread；
不依赖 OpenCV、相机 SDK 或 OpenVINO。也可构建已有 CMake 目标 `mv-imu-drift`。
默认使用项目的 `src/config`；相对配置/数据路径按项目根目录解释。
支持 `RM_VISION_CONFIG_ROOT`（未设置或为空使用默认配置）；默认读取当前 `active_profile` 的 IMU 配置及安装旋转。
`--device` 仅覆盖本次串口地址，`--motor-state`、`--thermal-state`、`--note` 为自由文本备注，
未提供时状态为 unspecified，不会自动推断机械静止或冷机状态。

Q 加回车或 Ctrl+C 提前结束并分析。终端输入 EOF 不会终止定时采集。
首个有效样本等待超过 30 秒则保存无数据诊断并退出。首帧后总采集时长按主机单调时钟计，
断线期间仍计时，不会无限等待。退出码：0 有有效数据并完成分析，1 参数/读写错误，
2 无有效数据。短记录也可返回 0，不代表漂移精度合格。

## 输出与统计解释

会话位于 `artifacts/imu_drift/<Unix微秒时间戳>/`，不会覆盖旧目录：

- `session.yaml`：版本、部署 profile、有效串口参数、安装外参快照、实验备注及结束状态。
- `samples.csv`：所有已解码姿态帧的原始数值、时间、序号、有效性与拒收原因，格式不变。
- `protocol_diagnostics.csv`：type 5/6、payload 版本、陀螺标定及机构状态、拒收原因；
  按代次/序号/MCU 时间关联原样本。会话及分析报告汇总状态计数，旧会话仍可分析。
- `analysis/<时间戳>/report.yaml`：逐段、逐分钟统计和拒收数量。
- 同目录 `seconds.csv`：按 MCU 时间合并的每秒均值。
- 同目录 `README.md`、`plots.html`：摘要及离线 SVG 曲线，各段独立显示。

同时接受 type 5 与 type 6 v2。type 6 检查载荷结构、READY/FINITE 和姿态数值；
陀螺标定状态、机构就绪状态只记录，不作为静止实验门槛。启动时显示 profile、设备、
波特率和输出目录。详见 [协议门槛](../tool/CALIBRATION.md#imu-诊断与手眼门槛)。

CSV 四元数为 IMU 到惯性系的 wxyz；角速度为协议输出的 IMU 机体系 rad/s，
并非确认未经滤波/补偿的传感器原始输出。协议没有温度和加速度。
CRC 错误帧由链路层拒收，不产生姿态行；累计 CRC 计数反映在之后的链路快照中。
序号跳号分别报告，不直接宣称为已确认串口丢包。

计算副本归一化四元数，使用项目统一入口 R_WG = R_WI × R_GIᵀ。
yaw/pitch/roll 是世界系 ZYX Euler 角展开后相对段首的变化，单位为度；
SO(3) 为当前姿态与段首的最短旋转夹角，范围 0–180°，不用于累计圈数。
段内任一有效姿态的绝对 pitch 达到 85°时，整段 Euler 统计/曲线不可用，
`seconds.csv` 的 Euler 列仍保留数值但 `euler_valid=0`，应忽略这些列。

重建会话、时间/序号回退或有效数据中断超过 1 秒会分段，不跨段拼接和拟合。
分段只表示数据参考可能不连续，不能据此判断实际物体运动。
拟合使用每秒均值和实际平均 MCU 时间，各秒等权；不用波动的帧频给某段额外权重。
不少于 60 秒才报告长期线性趋势；逐分钟至少 55 个秒桶才报告该分钟斜率。
常量序列的 R² 为 null（不适用），不能解释为漂移严重。
报告还包含去趋势 RMS、原始有效角速度样本的均值/标准差和逐分钟秒均值统计。
角速度均值仅在机械静止成立时可用于研究零偏，工具不会将其直接写为补偿参数。

报告没有合格线。持续单向变化且冷机/热机斜率不同，提示需要研究预热相关漂移；
静止稳定也不能排除运动过程中的姿态误差。若静止稳定，下一轮做转动后返回同一机械位置实验。
请提供整个会话目录；采用不同轮次拟合和验证补偿，避免只适用于一次采集。

## 手动验收

1. 机械静止录满 15 分钟，确认 CSV、逐分钟报告和本地 HTML 曲线完整。
2. Q 回车及 Ctrl+C 分别提前结束，确认已有数据保留且生成短记录报告。
3. 断线重连后确认新段出现，各段起点独立、无跨段斜率。
4. 修改当前部署配置后离线分析旧会话，确认仍使用采集快照，且不打开串口。

本轮已完成构建、脚本语法/帮助入口、菜单和伪终端串口验收：覆盖 type 5/6、结构错误、
无效姿态、重复/回退、断连后重开、跨会话分段，以及旧会话离线分析；核对出站消息只有
HELLO/SYNC。自动采集的合成数据在会话备注中标明，不能作为实机漂移实验。
实际机械静止、电机状态、真实串口及长时间漂移行为仍待用户实机验证。
